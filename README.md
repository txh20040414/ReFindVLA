# ReFindVLA

ReFindVLA is a CARLA-Air based UAV dynamic-target reacquisition system. The repository contains the current control code and the Linux GPU operation manual for the Qwen2.5-VL + LoRA high-level decision service.

## System boundary

```text
Qwen2.5-VL + LoRA (Linux GPU)
        ↓ high-level JSON: phase/view/confidence/hold_seconds/reason
CARLA-Air local runner
        ↓ belief search + candidate verification + waypoint planning
AirSim local controller
        ↓ low-level velocity/yaw commands
UAV simulation
```

Qwen is a high-level planner. It does not directly output `vx/vy/vz/yaw_rate`; those values are generated by the local controller after semantic waypoint planning.

## Repository contents

- `Carla_code/Code/main_interactive_track/`: current online CARLA-Air/AirSim closed loop;
- `Carla_code/Code/collect_data_code/`: current decision-level data collection and export utilities;
- `Carla_code/Code/model_server.py`: Qwen2.5-VL + ReFindVLA LoRA HTTP service;
- `Carla_code/models_/mode_v2/`: locally recorded LoRA adapter files, if included in this checkout;
- `Carla_code/docs/LINUX_GPU_VLA_EXPERIMENT.md`: step-by-step Linux, GPU, server, simulator and controller instructions;
- `Carla_code/requirements-client.txt`: local controller dependencies;
- `Carla_code/requirements-server.txt`: GPU inference service dependencies.

The full CARLA-Air executable and the Qwen base model are external dependencies and are not committed here. Do not commit credentials, private model paths, or generated experiment outputs.

## Start here

Read [`Carla_code/docs/LINUX_GPU_VLA_EXPERIMENT.md`](Carla_code/docs/LINUX_GPU_VLA_EXPERIMENT.md) before running anything. The service must be started on the GPU machine first, followed by the CARLA-Air/AirSim controller.

## Current status

The repository contains the implementation and a switch for the reviewer-requested no-VLA control condition:

```bash
export RECOVER_USE_REMOTE_VLA=0
export RECOVER_REMOTE_REQUIRED=0
```

This switch does not create experimental results by itself. Any new ablation result must be produced by running the documented protocol and recorded with the corresponding Git commit and environment variables.
